# Docs-as-Code / Diátaxis — Prior Art Note

> Research date: 2026-09-22 · Sources: diataxis.fr (framework, map, start-here), canonical.com blog (adoption), docs-as-code practitioner guides (MkDocs/Docusaurus structuring).

## What it is
The professional-technical-writing movement to treat documentation as source: **docs live in the repo, are versioned in git, built by SSGs** (MkDocs, Docusaurus, Sphinx, Hugo), and — critically — **structured by user-need categories**. The dominant framework is **Diátaxis** (Daniele Procida; adopted by Canonical, Gatsby, Cloudflare, Read the Docs community):

| Mode | Need | Answers |
|------|------|---------|
| Tutorials | learning | "teach me" (step-by-step) |
| How-to guides | task | "how do I do X" |
| **Reference** | information | "what is it exactly" (dry, complete, mirrors code structure *like a map*) |
| **Explanation** | understanding | "**why** does it work this way" (context, mental model) |

- **Single source of truth**: content written once, included in multiple pages (MkDocs snippets / Docusaurus includes) so updates propagate — the docs version of SSRL's "one layer feeds all projections" (P7).
- **Docs-as-Code automation**: sidebar/nav/validation driven by structured directories; "structure allows machines to understand the documentation." Reference architecture "should follow the machinery's structure so one maps to the other."

## Where it stops
- **Human-written, hand-maintained**: every Diátaxis practitioner's #1 failure is drift — the explanation and reference rot as code changes and nobody re-writes them ("no pipeline can substitute for author judgment," and the Canonical post admits transformation takes years).
- No automatic coupling between docs and the code's actual facts; links break; explanations become historically interesting but false.
- Diátaxis is a *taxonomy+workflow*, not an executable contract — no confidence/evidence, no provenance for claims.

## Relevance to SSRL
- **H3 (living narrative) is §the automation of Diátaxis** — specifically the "Explanation" (why, mental model) and "Reference" (what is it, map-of-code) quadrants, generated by the layer and kept in sync by derivation (P5 continuity). Diátaxis proves there is *recognized, adopted demand* for exactly this content; nobody auto-maintains it → **least-crowded projection** (see w2 synthesis, RN-1).
- **H2 (progressive zoom)** maps to Diátaxis's "reference mirrors the code's architecture like a map" — the drill-down view is the map, human-scale.
- **W3 follow-up**: practitioner pain around doc drift is a W3-citable failure story that strengthens SSRL's adoption argument.
- Single-source-of-truth pattern validates SSRL's projection-agnostic layer (one model, many projections).
